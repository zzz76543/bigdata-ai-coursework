# 概念学习资料生成器（concept-learning）

把任意一个新概念，转成一份**能自洽、可核查、有个人理解**的学习资料。

## 适用场景

- 用户给出一个陌生概念（如"注意力机制""上下文窗口""向量检索"），希望快速建立系统认知；
- 需要为某个概念整理一份结构化笔记，供复习或提交作业；
- 需要把零散的理解固化成带来源依据的文档，避免"凭感觉理解"。

不适用：单纯查词义（查字典即可）、只需要一句定义、或已经有成熟完整资料只需转发的情况。

## 输入信息

至少需要以下内容，缺失时先向用户确认再动笔：

| 输入项 | 说明 | 必需 |
| --- | --- | --- |
| 概念名 | 要学习/解释的概念（中英文均可） | 是 |
| 学习背景 | 用户的身份、已掌握的知识、这门概念用在哪 | 否（可推断） |
| 个人经历 | 用户与该概念相关的真实接触（踩过的坑、做过的项目） | 否（有则更真实） |
| 目标读者 | 是写给自己复习，还是交给老师/同学看 | 否（默认"可交作业"标准） |

## 生成步骤

1. **确认概念边界**：先明确这个概念属于哪个领域，和哪些相邻概念容易混，防止写偏。
2. **检索权威来源**：优先官方文档、论文、一手博客，不把二手转述当依据（见「资料来源要求」）。
3. **写出个人解释**：用一句话讲清"它到底是什么"，再用自己的话展开，**不照抄定义**。
4. **拆解核心机制/组成**：讲清它是"怎么工作的"，包含关键部件或关键流程，必要时配图/表。
5. **给一个具体场景**：用一个真实、具体的例子（优先用户自己的经历）说明它怎么落地。
6. **列出易混淆点与边界**：指出最容易误解的地方，以及它"做不到什么""不适用什么"。
7. **附可核查来源**：每条来源给出标题 + 可点击 URL，保证读者能自己查到原文。
8. **自检**：按下方「自检要求」逐条核对，缺一项就补齐。

## 输出结构

每份资料固定为五段式，缺一不可：

1. **个人解释** —— 用自己的话讲清概念是什么；
2. **核心机制 / 组成** —— 它是怎么工作的，由哪些部分构成；
3. **一个具体应用场景** —— 真实可感的落地例子；
4. **易混淆问题 / 使用边界** —— 常见误解 + 能力边界；
5. **可核查资料来源** —— 带链接的来源清单。

输出格式：HTML（自包含、离线可读）或 Markdown 均可，优先 HTML 以便直接浏览。

## 资料来源要求

- 优先**官方文档、原始论文、一手博客**；二手转述（知乎/公众号解读）只能作补充，不作主依据。
- 每条来源必须同时给出**标题 + 完整 URL**，让读者能点开核实。
- 不编造链接、不把"我记得好像是"当来源。查不到就写"待查证"，不硬凑。

## 自检要求

写完必须逐条核对，全部满足才算完成：

- [ ] 五段式结构齐全，没有缺段；
- [ ] "个人解释"是自己的话，不是复制定义；
- [ ] 核心机制/组成有实质内容，不是空话堆砌；
- [ ] 应用场景具体、可想象，不是"广泛用于各行各业"这种套话；
- [ ] 易混淆点确实指出了"容易搞错的地方"，边界说清了"做不到什么"；
- [ ] 每条来源可点击、真实存在，且确实支撑了文中的说法；
- [ ] 全文无敏感信息（API Key、密码、个人隐私）。

> 本 Skill 是通用模板：把"输入信息"里的概念换成任何一个新主题，重复上述步骤即可产出新资料，而不是为某几个固定概念写死的一段话。
