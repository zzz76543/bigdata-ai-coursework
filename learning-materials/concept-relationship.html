概念关系说明

上下文、Agent、Skill 三者如何串成一条能力闭环

上下文是 Agent 的"燃料"，Agent 是"行动者"，Skill 是 Agent 反复行动后沉淀出的"可复用能力"——三者不是并列的三个词，而是一条首尾相接的循环。

01一句话总览
概念一句话定位在闭环里的角色
上下文（Context）模型当下能参考的全部文本，是它的"工作记忆"燃料 / 记忆
Agent（智能体）能调用工具、自己决定下一步的 AI行动者 / 决策者
Skill（技能）把成功做法打包成的可复用流程可复用的能力
02关系流程图
① 上下文 → Agent：给 Agent 喂记忆和背景，Agent 才能做对决策 ② Agent → Skill：Agent 反复做同一类任务，把成功路径固化成 Skill ③ Skill → 上下文：Agent 按需加载 Skill，加载本身又占用、依赖上下文
03重点一：上下文如何影响 Agent 的工作

上下文是 Agent 做决策的全部依据，它的质量直接决定 Agent 的表现上限。

  • Agent 只会"在上下文里思考"。它不知道上下文之外的东西。所以 Agent 能不能想起"这个坑之前踩过"，取决于这条经验有没有被放进上下文。
  • 给对上下文，Agent 少犯错。我这几天让 Kai 干活，它之所以每次都能"接着上次继续"，是因为记忆文件里的"网络会间歇阻断""PAT 要勾 repo 主项"这些结论被自动注入了上下文，而不是它真的"记得"。
  • 上下文也不是越多越好。塞得太多会触发 context rot，反而让 Agent 抓不住重点。所以好的上下文要"精选"，把最有用的信息放进去，而不是把历史全摊开。

一句话：上下文决定 Agent"知道什么"，而"知道什么"决定了它能做成什么样。

04重点二：Skill 如何沉淀可复用的任务知识

Agent 做一次是"经验"，把经验结构化写成 Skill，才变成"能力"。这一步是从"碰巧成功"到"稳定复现"的关键跨越。

  • 经验是散的，Skill 是结构化的。Agent 某次成功可能靠临场发挥，下次未必复现；Skill 把"输入、步骤、输出、自检"写成固定流程，让结果稳定。
  • Skill 让"一次性正确"变成"每次都正确"。以我这周的经历为例：Kai 摸索出的"绕代理 + 禁弹窗 + 内嵌令牌"推送办法，如果只留在聊天里，下次还要重新踩坑；写进 safe_push 之后，每次推送直接调用。
  • Skill 又反过来增强 Agent。Agent 加载 Skill 后，相当于"临时获得了一项专门能力"——这正是闭环的意义：Agent 沉淀出 Skill，Skill 又让 Agent 更强。

一句话：上下文让 Agent"会想"，Skill 让 Agent"会做"，而 Agent 在两者之间把经验变成能力。

05关系小结

三者的关系可以用一句话收束：

上下文是 Agent 的记忆，Skill 是 Agent 的肌肉记忆；Agent 靠上下文做对每一次决策，再把反复做对的事沉淀成 Skill，而 Skill 的加载又离不开上下文——三者首尾相接，构成一个不断自我增强的循环。
